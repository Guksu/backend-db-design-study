# backend-db-design-study

실무에서 마주치는 백엔드 · 데이터베이스 설계 문제를 **문답으로 설계하고, 핵심 주장은 실험으로 검증해서 기록**하는 공부 저장소입니다.

## 진행 방식

1. **상황**: 케이스와 요구사항을 정한다
2. **문답**: 한 번에 하나씩 묻고 답한다. 테이블, 컬럼, 타입, 제약조건까지 내가 먼저 답하고 피드백을 받아 고친다. 시간이 걸려도 처음부터 끝까지 같이 설계한다
3. **반영**: 합의한 만큼만 SQL · 코드 · 화면에 반영한다
4. **검증**: 설계의 핵심 주장("락이 없으면 오버부킹이 난다" 같은)을 실험으로 확인하고, 시각화 화면에서 눈으로 본다. 실험은 `experiments/`의 테스트로도 남긴다
5. **기록**: 문답과 결론을 단계별 문서로 정리한다

### 다음 케이스 후보

- **선착순 쿠폰 발급**: 수량 제한, Redis 원자 연산
- **좋아요 · 조회수**: 쓰기가 몰리는 카운터, 모아서 반영하기
- **피드 · 타임라인**: fan-out on write vs read, 커서 페이지네이션
- **주문 · 결제**: 재고 차감, 멱등성, 보상 트랜잭션
- **랭킹**: Redis Sorted Set, 동점 처리
- **시간 예약(병원 · 미용실)**: 시간대 겹침 방지, 배타 제약(EXCLUDE)

## 실행

Docker(OrbStack), Node 22(`nvm use`), pnpm이 필요합니다.

```bash
pnpm install
pnpm infra:up    # PostgreSQL, Redis
pnpm dev         # 시각화 화면 http://localhost:5288
pnpm test        # 모든 실험 실행
pnpm psql        # DB에 직접 접속해서 들여다보기
```

## 구조

```
cases/
  NN-케이스/
    README.md        상황, 요구사항, 단계 목록
    stepNN-주제.md   단계별 문답 기록
    schema.sql       합의한 스키마
    api.ts, ui/      실험 API와 시각화 화면
    experiments/     설계를 검증하는 실험 (Vitest)
PRODUCT.md           실험실이 누구를 위해 무엇을 증명하는지
DESIGN.md            실험실 화면의 디자인 시스템 (색 · 글자 · 부품 규칙)
lab/                 실험 공용 도구 (DB 연결, 스키마 초기화, 카탈로그 · 실행 계획 읽기)
server/              실험 API 서버 (Hono)
web/                 시각화 화면 (React + Vite)
  src/erd/           DB 카탈로그로 그리는 ERD 캔버스 (React Flow)
  src/sim/           시뮬레이터 부품: 트레이스 타임라인, 재생, 히트맵
```

각 케이스는 PostgreSQL 안에서 자기 이름의 스키마(예: `ticket`)를 쓰고, 실험을 시작할 때마다 스키마를 지우고 다시 만들어 같은 상태에서 출발합니다.
