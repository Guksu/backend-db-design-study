# Case 01. 콘서트 티켓 예매

## 상황

인기 콘서트의 예매가 열리는 순간 수만 명이 동시에 들어와 1,000석을 두고 경쟁한다.

## 요구사항

> 초안. 문답하면서 같이 다듬는다.

- 회차를 고르고 좌석을 골라 예매한다.
- 좌석을 고르면 일정 시간 점유되고, 그 안에 결제하면 확정, 아니면 풀린다.
- 한 좌석이 두 사람에게 팔리면 안 된다(오버부킹 금지).
- 예매가 열린 직후 트래픽이 몰려도 서비스가 버텨야 한다.

## 단계

| Step | 주제 | 눈으로 확인할 것 | 기록 |
|---|---|---|---|
| 1 | ERD | 공연장 좌석 배치, 제약조건이 막는 모습, 동시 INSERT 경쟁 | [step01-erd.md](step01-erd.md) |
| 2 | 점유와 만료 | 좌석이 점유됐다가 시간이 지나 풀리는 타임라인 | |
| 3 | 동시성 문제 재현 | 100명이 한 좌석에 몰릴 때의 요청 타임라인과 오버부킹 좌석 | |
| 4 | DB 락 전략 비교 | 전략별 성공 · 실패 수, 응답시간 분포, 커넥션 대기 | |
| 5 | Redis로 점유하기 | DB 전략과의 처리량 비교 | |
| 6 | 대기열 | 대기 순번이 줄어드는 모습, 초당 입장 수 | |
| 7 | 결제 정합성과 멱등성 | 더블 클릭 · 타임아웃 시나리오의 결과 | |
| 8 | 다중 서버에서 깨지는 것들 | 서버 1대 vs 3대 결과 비교 | |
